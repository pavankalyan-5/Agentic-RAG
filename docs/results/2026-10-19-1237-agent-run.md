**Answer:**

> You can run code at application startup and shutdown by registering a lifespan handler in your Starlette application. This is done by defining an async context manager function decorated with `@contextlib.asynccontextmanager` that yields control between startup and shutdown code. For example:
> 
> ```python
> import contextlib
> from starlette.applications import Starlette
> 
> @contextlib.asynccontextmanager
> async def lifespan(app):
>     async with some_async_resource():
>         print("Run at startup!")
>         yield
>         print("Run on shutdown!")
> 
> routes = [ ... ]
> app = Starlette(routes=routes, lifespan=lifespan)
> ```
> 
> Starlette will run the startup code before serving requests and the shutdown code after all connections are closed and background tasks complete [72].

**Answer:**

> To limit the size of uploaded files in multipart forms, you can configure the `max_body_size` parameter on the application, router, mount, or route, or use the `RequestBodyLimitMiddleware`. This limit applies to the total request body size, including uploaded files and multipart encoding overhead. For example, you can set `max_body_size` on a route like this:
> 
> ```python
> Route("/upload", upload, methods=["POST"], max_body_size=100 * 1024 * 1024),
> ```
> 
> or use middleware:
> 
> ```python
> middleware = [
>     Middleware(RequestBodyLimitMiddleware, max_body_size=10 * 1024 * 1024)
> ]
> ```
> 
> Additionally, when parsing the form with `request.form()`, you can limit the size of each non-file field with `max_part_size`, but uploaded files themselves are spooled to temporary storage and are not limited by `max_part_size`. Therefore, the main control for uploaded file size is via `max_body_size` limits.
> 
> This approach ensures that the entire request body, including multipart file data and encoding overhead, does not exceed the specified size limit, preventing excessively large uploads.
>

**Answer:**

> You can run code at application startup and shutdown by registering a lifespan handler in your Starlette application. This is done by defining an async context manager function decorated with `@contextlib.asynccontextmanager` that yields control between startup and shutdown code. For example:
> 
> ```python
> import contextlib
> from starlette.applications import Starlette
> 
> @contextlib.asynccontextmanager
> async def lifespan(app):
>     async with some_async_resource():
>         print("Run at startup!")
>         yield
>         print("Run on shutdown!")
> 
> routes = [ ... ]
> app = Starlette(routes=routes, lifespan=lifespan)
> ```
> 
> Starlette will run the startup code before serving requests and the shutdown code after all connections are closed and background tasks complete [72].
